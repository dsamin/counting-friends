# Counting Friends — Native iPad App (Capacitor)

The same React/Vite codebase ships **two** ways:

1. **Web PWA** — `npm run build` → GitHub Pages (`/counting-friends/`, service worker on). Unchanged.
2. **Native iPadOS app** — a Capacitor wrapper around the same bundle, runnable on the
   iPad Simulator and architected for a later App Store submission.

This doc covers the native app. Full design + review history:
`docs/superpowers/specs/2026-06-17-ipad-capacitor-app-design.md`.

---

## Build & run on the iPad Simulator

Prereqs (one-time): **Xcode** + **CocoaPods** (`brew install cocoapods`; needs `/opt/homebrew/bin` on PATH and `LANG=en_US.UTF-8`).

```bash
# 1. Build the web bundle in native mode + copy it into the iOS project
npm run build:native && npx cap sync ios

# 2. Boot an iPad simulator
xcrun simctl boot "iPad Pro 11-inch (M4)"   # or any iPad from `xcrun simctl list devices`
open -a Simulator

# 3a. Easiest: let Capacitor build/run it
npx cap run ios --target "iPad Pro 11-inch (M4)"

# 3b. Or build explicitly (no code signing needed for the simulator):
xcodebuild -workspace ios/App/App.xcworkspace -scheme App -configuration Debug \
  -sdk iphonesimulator -destination 'platform=iOS Simulator,name=iPad Pro 11-inch (M4)' \
  CODE_SIGNING_ALLOWED=NO CODE_SIGNING_REQUIRED=NO -derivedDataPath ios/DerivedData build
APP=ios/DerivedData/Build/Products/Debug-iphonesimulator/App.app
xcrun simctl install booted "$APP"
xcrun simctl launch booted app.countingfriends.game
xcrun simctl io booted screenshot /tmp/shot.png   # capture evidence
```

> First build is slow (compiles Capacitor + Pods) and the first 26.x simulator boot is
> cold — allow several minutes; it is not a hang. `xcodebuild build` only *builds*; you
> must `simctl install` + `simctl launch` separately. Raw `xcodebuild` also tries to
> code-sign unless `CODE_SIGNING_ALLOWED=NO` is passed.

To open in Xcode instead: `npx cap open ios`.

## How it works

- **Dual build, one codebase.** `vite.config.ts` reads two env vars:
  - `VITE_BASE` — asset base path. Web defaults to `/counting-friends/`; native uses `/`
    (Capacitor serves from `capacitor://localhost`, so assets must be root-relative).
  - `CAP_BUILD=1` — disables `vite-plugin-pwa`. A service worker inside WKWebView causes
    stale-cache white-screens and is redundant (the app bundles assets locally).
  - `npm run build:native` = `cross-env CAP_BUILD=1 VITE_BASE=/ npm run build`.
- **`capacitor.config.ts`** — `appId: app.countingfriends.game`, `webDir: dist`, cream
  background, splash auto-hide safety net. `server` is left default (offline).
- **Native seams live in `src/native/`** (all no-op on web via `Capacitor.isNativePlatform()`):
  - `bootNative.ts` — hides the status bar (immersive) + dismisses the splash; called once from `main.tsx`.
  - `feedback.ts` — `celebrate()` (success haptic) + `tap()` (light impact), wired into
    `PlayScreen` (confetti effect + animal tap), suppressed under reduce-motion.
  - `capacitorTtsEngine.ts` — a composite `AudioEngine`: SFX/`ensureAudio` reuse the WebAudio
    engine; speech uses native iOS TTS (`@capacitor-community/text-to-speech`, system en-US
    voice) because Web Speech is unreliable in WKWebView. `onSpeakingChange` is synthesized
    around the async plugin so the ReplayPill "speaking" animation still fires.
  - `App.tsx` selects the native engine on native, WebAudio on web.
- **Safe areas** — the three absolutely-positioned chrome elements use
  `max(<original>, env(safe-area-inset-*))`: Back button + ReplayPill (inline styles),
  parental gate (`.cf-gate` in `app.css`). On web `env()` is 0 (positions unchanged); on
  device the inset is added so nothing is clipped by rounded corners / the home indicator.
- **Scroll lock** — `index.css` body is `position:fixed; overflow:hidden; overscroll-behavior:none`
  to kill WKWebView rubber-banding.
- **Plugins:** `@capacitor/{core,ios,cli,app,haptics,splash-screen,status-bar}` (7.x) +
  `@capacitor-community/text-to-speech` (6.1.0, the Capacitor-7-compatible line).

## Verification (2026-06-17)

- **Native shell:** builds, installs, launches on iPad Pro 11" (M4) simulator and renders
  the real game (Start screen) — proving the base-path + service-worker fix works in WKWebView.
- **PlayScreen** (portrait + landscape) verified on the exact native bundle at iPad
  dimensions: chrome correctly placed, 3 animals / 3 numbers (Easy), confetti on correct,
  clean rotation reflow with no clipping. The ReplayPill `--speaking` state on load is the
  observable proxy that the voice prompt fires.
- **Flows:** Playwright e2e 6/6 (tier select, correct→celebrate→advance, wrong→no-fail,
  parental-gate hold-3s, settings, back) — same code the WKWebView runs.
- **Regression:** typecheck, lint, 155 unit/component tests, web build all green; the web
  PWA build/deploy path is untouched.

**Owner spot-checks (not agent-verifiable — no audio/touch on a headless simulator):**
actual voice/SFX audibility, haptic feel, and the 3-second gate press on a real device.
